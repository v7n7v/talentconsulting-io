# Taco v1.2 — staging foundation

Published source version: **v1.2**, on `codex/taco-v1.2`. This tag identifies the Taco upgrade release; the existing internal npm package version remains unchanged.

## Included

- Upgraded Taco branding, animated landing examples and career workspace from the reviewed staging source.
- Chat containment: a model-supplied confirmation cannot queue an application. Taco directs the candidate to Job Search's explicit Prepare action.
- Strict preparation contracts, authority/budget policy and an injectable command issuer with deterministic identity, replay handling and expiry checks. The issuer is a local foundation without a production storage adapter or endpoint.
- Firestore rules and emulator checks that prevent clients from changing account lifecycle authority. This additional rules restriction is published here but has not been deployed.
- A private, synthetic Cloud Tasks/Google Workflows recovery comparison, with bounded worker code, versioned workflow definitions and a staging driver. Google Workflows is selected for the first sequential pilot.
- The implementation plan, architecture, competitive strategy and staging runbook.

## Staging and verification

The [review environment](https://taco-upgrade-staging-1016393231808.us-east1.run.app/) serves web revision `taco-upgrade-staging-00003-f6p`, built from sanitized snapshot `aee254627d6764cb61cd61c0a5056d5786a22fa3`. This source release also contains the local issuer, lifecycle rules and synthetic recovery tooling; it does not claim that these additions are wired into the deployed web runtime.

Recorded foundation checks: 49 focused tests, 331 assistant-harness tests, 21 isolated Firestore/Auth emulator tests, passing type check and a 200-page staging build. The unchanged landing passed browser checks at 320, 390, 430, 768, 1024 and 1440 pixels; the deployed containment update also passed a browser smoke check. No authenticated, provider-backed candidate journey was exercised.

The publication checkout was checked again: 48 focused preparation/recovery/staging tests, all 21 isolated emulator tests, type checking and the release-safety gate passed. These checks exercised the assembled source; they did not repeat the earlier live cloud experiment or staging build.

Two live synthetic recovery rounds passed 40/40 bounded cases, with no duplicate committed step outputs and stale completions rejected. The version rollout changed metadata only; it does not establish compatibility across changed worker code or exactly-once provider execution. Local evidence and cloud receipts are retained outside the public source tree.

The public source omits the deployment-specific `staging-build.json` marker and an unrelated USB utility. The tracked production build fixture contains only public-prefixed settings; server settings belong in runtime configuration. Existing repository ancestry and reference documents are preserved.

## Remaining work

P1 remains partial. Independently recoverable authority/deletion journaling, restore quarantine, authenticated issuance and transactional worker claim/commit integration must precede private-data runtime use. P2–P6 remain planned, including recoverable analysis, complete packet review and Daily focus with notifications.

Paid AI, job, email and payment providers are unconfigured in this staging runtime. Existing design-baseline regressions and one accepted dependency advisory remain; this is a staging foundation release, not production readiness. The recovery worker must remain private behind Cloud Run IAM and its separate synthetic database.

The original Taco project and production deployment are preserved. No real-user email, payment or external application submission is part of this release.
