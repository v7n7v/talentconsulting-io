# Interview and learning tool audit

Date: 2026-09-28. Scope: source review in the isolated `Taco-upgrade` checkout. This report makes no claim that live AI, billing, microphone, WebSocket, Firestore, or device behavior has passed runtime testing. No product code or live data was changed.

Evidence labels: **Source-confirmed** means the active call path and implementation were traced; **Source risk** means code supports a failure scenario that still needs reproduction; **Product judgment** means a relevance/usability recommendation, rather than a measured user-research result. P1 blocks release of the **affected capability or claim** as production-ready because of a broken core promise or evidence-integrity problem; it does not automatically block the isolated preview, unrelated core journeys, or the entire product. Unverified timing/account-transition risks are staging gates, not proof of real account disclosure. P2 is an important workflow/recovery/usability defect; P3 is a lower-priority improvement. There are no P0 findings established by this review.

The central conclusion is to keep Interview prep, Story bank, and focused skill learning, but finish their actual connections before adding more modes. The interface currently describes an integrated proof-and-practice loop more completely than the handlers implement it.

## What is solid and should be retained

- Quick Drill is the default; live microphone mode is not entered automatically (`interview-sim/page.tsx:248`). Generation, grading, and session endpoints use authenticated/rate-limited guards; stored sessions are under the authenticated user's namespace (`app/api/interview/sessions/route.ts:67`, `:97`, `:115`). This is a useful foundation, not proof that quota/session contracts are correct.
- Application deep links have syntax/availability checks and a retry path; selected application resolves role/company/JD/resume ID (`interview-sim/page.tsx:405`, `:445`). Actual-interview debrief creation validates application ownership and uses a payload-bound idempotency key (`app/api/agent/debriefs/route.ts:81`, `:123`, `:142`).
- Story CRUD normalizes strings and uses the owner namespace. Coverage counts saved categories instead of manufacturing a readiness percentage, and legacy migration uses deterministic canonical IDs (`lib/story-bank.ts:238`, `:319`, `:484`; `app/api/agent/stories/coverage/route.ts:53`).
- Skill Bridge no longer seeds invented gaps for empty accounts; unmeasured skills can render as unproven. Its grading API explicitly fails when the provider cannot grade instead of manufacturing an assessment (`skill-bridge/page.tsx:83`, `:449`; `app/api/skill-bridge/verify/route.ts:181`). This standard should also apply to interview assessment.
- Memory output passes through HTML sanitization, and deletion verifies item ownership (`MemoryPanel.tsx:373`; `app/api/vault/delete/route.ts:20`). Existing data remains readable independently of paid generation access.
- Live hook cleanup stops media tracks, timers, sockets, and audio contexts (`hooks/useGeminiLiveAvatar.ts:425`). UI distinguishes cap errors from microphone/network faults and supplies an upgrade route only for entitlement errors (`interview-sim/page.tsx:1672`; `useGeminiLiveAvatar.ts:133`).

## Findings: Interview Studio and debriefs

### IL-01 — P1 — Full Mock calls the wrong generation branch

**Source-confirmed.** Client sends `interviewType: 'mock'`, while the API's persona- and JD-aware branch requires `'mock-interview'` (`app/suite/interview-sim/page.tsx:515`; `app/api/gauntlet/generate/route.ts:93`). The alternate drill prompt does not use the JD and does not apply the selected persona (`generate/route.ts:154`). The default `mixed` and `case` categories also fall into a leadership-focused fallback expression (`:160`). Users can configure a carefully targeted mock and receive generic questions.

**Upgrade / acceptance:** Use a shared discriminated request schema with explicit mode/type/persona; selected JD and persona must appear in the resolved mock context. Contract tests cover all five interview types, six personas, and the actual UI payload. No silent downgrade after a schema or entitlement error. Quick Drill's advertised question count must match the offered count.

### IL-02 — P1 — A Free user's completed typed practice can be denied its final debrief by double metering

**Source-confirmed, scoped to Taco's Free lifetime allowance.** Successful question generation increments `gauntlets` (`app/api/gauntlet/generate/route.ts:196`). Session grading again checks the same feature and increments it (`app/api/interview/session-grade/route.ts:85`, `:148`). Free has three lifetime gauntlet uses (`lib/usage-tracker.ts:39`), and its API guard enforces that cap (`lib/api-auth.ts:225`). A Free account at two uses can therefore generate questions using its last allowance and then fail the cap check when requesting feedback. Standard (`pro`), Max (`studio`), and God are unlimited for this lifetime meter (`lib/usage-tracker.ts:200`; visible plan mapping in `lib/plan-identity.ts:75`, `:102`); **this finite-cap debrief lockout does not apply to them**, although ordinary rate limits/provider faults are separate concerns. This finding concerns product feature accounting, not the user's Codex allowance.

Study Cards has a related Free-tier mismatch: it is gated by `gauntlets` at session creation and generation before checking the separate `flashcards` allowance (`app/api/interview/sessions/route.ts:97`; `app/api/gauntlet/generate/route.ts:18`, `:28`, `:86`). Live token minting checks usage but does not record a usage event; ungraded live sessions are not metered there (`app/api/voice/live-token/route.ts:28`, `:86`). These are accounting contract defects, not evidence of an unexpected monetary charge.

**Upgrade / acceptance:** One idempotent allowance reservation per practice session, valid through grading/retry; explicitly choose counting policy for failed/abandoned/live sessions. For Free, verify zero, one, two, and three remaining uses, a fresh account's sequential completed sessions, repeated grades, concurrent starts, and interrupted connections. Standard/Max/God must not gain an artificial lifetime cap during this repair. Keep independent rate-limit tests separate. Free study-card access must use its intended allowance, not an exhausted interview allowance. Show allowance consumption before start; a permitted session must remain eligible for its debrief and retry without an additional lifetime-use check.

### IL-03 — P1 — The selected resume and story evidence do not reach the practice engine

**Source-confirmed.** Readiness says the selected resume is “linked for proof checks” and that saved STAR stories fuel practice (`interview-sim/page.tsx:190`, `:201`). Session creation stores `resumeVersionId`, but generation receives no resume content/ID or stories (`:470`, `:509`); grading receives no source IDs/evidence (`:655`); live connect receives persona/JD/style only (`:611`). Backend grading does not retrieve session context, resume, or stories (`app/api/interview/session-grade/route.ts:116`), and live token construction likewise uses only the supplied fields (`live-token/route.ts:35`). Displayed Story Bank matches include up to five stories even when all tag scores are zero (`interview-sim/page.tsx:383`).

**Upgrade / acceptance:** Resolve an owner-checked, revision-bound interview brief server-side containing selected application, confirmed source resume, user-approved stories, and source IDs. Explicitly distinguish matches from merely available stories. Changing resume/story selection must change the resolved engine input; no foreign or stale IDs, no claims that absent evidence was checked. Allow generic practice with honest labeling.

### IL-04 — P2 — Several visible customization choices are metadata only

**Source-confirmed.** Intensity and target duration are stored on the session (`interview-sim/page.tsx:478`) but never reach generation, grading, or live configuration (`:509`, `:611`, `:655`). Live wrap-up is fixed in the prompt to 5–7 questions (`app/api/voice/live-token/route.ts:138`). UI advertises 10–45 minutes and sharper follow-ups (`interview-sim/page.tsx:1453`). Study Cards receives `drillRole`, but its API prompt uses only JD/resume, ignoring role (`gauntlet/generate/route.ts:48`). The launcher's “Active voice” is also shown for typed modes.

**Upgrade / acceptance:** Each visible setting must have an observable supported effect and a mode-specific explanation, or be removed. Duration should be an honest estimate or an implemented timebox. Typed practice should not imply an active voice. Cards with only a target role must be about that role.

### IL-05 — P1 — “Saved debrief” is not a reliable persistence/recovery contract

**Source-confirmed.** Client PATCH responses are not checked when saving questions/transcripts/study completion (`interview-sim/page.tsx:540`, `:695`, `:703`, `:715`, `:1029`). Both grade APIs catch persistence failures yet return `{success:true}` (`session-grade/route.ts:133`; `whiteboard-grade/route.ts:97`). Typed Exit only changes phase instead of invoking `abandonSession` (`interview-sim/page.tsx:1056`); active records can remain active. Grading a final typed answer clears the draft before grading, with no dedicated retry-grade action (`:680`). Live End disconnects and clears the hook transcript before save/grade succeeds (`:711`; `useGeminiLiveAvatar.ts:397`). The live room's End button then disables when disconnected with no hook transcript (`interview-sim/page.tsx:1655`).

**Upgrade / acceptance:** Persist typed draft/answer and live transcript independently of provider grading, with explicit saved/saving/unsaved state. Separate “session ended”, “transcript saved”, and “grade ready”; retry a grade without recording another answer or consuming another allowance. A lost response must not duplicate sessions. Refresh/navigation/account switch must preserve only owner-scoped durable work and stop active media.

### IL-06 — P1 — Debrief Review cannot actually reopen the detailed debrief

**Source-confirmed.** History renders only a title, status, date, band, and Ask Taco; no handler retrieves or opens a session detail (`interview-sim/page.tsx:2031`). Ask Taco passes only a role-based sentence, not `session.id` or the transcript/grade (`:2043`). Immediate DebriefPanel omits generated per-answer feedback, rewrite tips, recommendations, story candidates, and whiteboard follow-up/nextSteps (`:1904`; compare `session-grade/route.ts:108`, `whiteboard-grade/route.ts:73`). Its “Next drill” only changes mode and opens assistant chat, without binding that drill to the next generated question (`interview-sim/page.tsx:1075`).

**Upgrade / acceptance:** Owner-checked session detail route/view with transcript, rubric, answer-level feedback, grading provenance, and retry state. History must reopen exactly the saved record after reload. A drill CTA starts a drill with the chosen focus and original context. Reviewed answer-to-story promotion produces an editable draft, never an automatic factual claim.

### IL-07 — P1 — Assessment conflates writing time, speech pace, and heuristic completeness

**Source-confirmed.** Both typed and spoken practice call `analyzeInterview` using whole room elapsed time (`interview-sim/page.tsx:649`); WPM is user words divided by whole-session minutes (`lib/interview-telemetry.ts:100`), including interviewer speech, pauses, and setup. Typed answers therefore receive speech-pacing judgments. Fallback grades use answer length, keyword/STAR markers, and invented per-answer offsets (`session-grade/route.ts:25`); whiteboard fallback scores field presence and solution length (`whiteboard-grade/route.ts:13`). These are disclosed in summary as deterministic fallback, which is better than hiding provenance, but still render the same Strong/Developing bands. Whiteboard validation requires only a prompt, so an empty answer can be graded (`whiteboard-grade/route.ts:58`). AI grading output itself has no runtime response-schema validation before rendering/persistence (`session-grade/route.ts:128`; `whiteboard-grade/route.ts:92`).

**Upgrade / acceptance:** No speech measures on typed practice. Audio pace requires measured speaking intervals and an uncertainty statement. Unavailable AI should yield “feedback unavailable” or explicitly unscored structural hints, not a substitute proficiency verdict. Reject empty/no-user-answer sessions and validate bounded rubric/feedback schemas. Fixture tests cover empty, one-line, long but wrong, malformed-provider, and provider-outage outputs.

### IL-08 — P1 — Live interviewer persona and launch lifecycle are inconsistent

**Source-confirmed for persona; source risk for timing.** UI sends IDs such as `faang-lead` (`interview-sim/page.tsx:87`, `:612`), while token voice/trait maps key on display names like `FAANG Tech Lead` (`app/api/voice/live-token/route.ts:14`, `:109`). All current IDs therefore resolve to default voice/traits. Live connection starts in an untracked 500 ms timeout (`interview-sim/page.tsx:610`); exiting before it fires can still connect afterward. Hook starts mic after socket setup; denial sets an error but leaves the socket connected (`useGeminiLiveAvatar.ts:271`, `:390`). No in-room mute or reconnect control exists in active LiveRoom (`interview-sim/page.tsx:1642`).

**Upgrade / acceptance:** Shared persona registry and explicit connection state machine with cancelable start. Start → immediate Exit and unmount must never open mic/socket later. Device test/permission explanation before quota reservation; mute, retry, and text fallback; denied mic closes or pauses the session honestly. Verify all persona voices in isolated staging. Do not claim the configured Gemini model remains available without a provider smoke check.

### IL-09 — P2 — Avatar mode is not a functioning distinct avatar implementation

**Source-confirmed.** `AvatarCanvas` requests `/models/interviewer.glb` (`components/interview/AvatarCanvas.tsx:53`), absent from this checkout's public asset inventory. It has no prop to register audio delivery; the active caller passes only speaking/connected (`interview-sim/page.tsx:1661`). The hook's `setOnAudioChunk` / `setOnTurnComplete` callbacks are never connected to this component, so even a supplied model would not receive lip-sync audio through this active path (`useGeminiLiveAvatar.ts:95`, `:300`). Audio fallback is implemented. Runtime CDN/WebGL behavior is unverified.

**Upgrade / acceptance:** Remove the separate mode from the primary choice set; optionally expose a tested avatar display inside Live. Require packaged asset availability, correct lifecycle disposal, actual audio/lip-sync integration, reduced-motion support, and low-power fallback before exposing it.

### IL-10 — P2 — Context selection has misleading exits and recovery edges

**Source-confirmed.** “Blank or pasted JD” has value `''`, but `applyApplication` returns before clearing selection for any unknown/empty ID (`interview-sim/page.tsx:365`, `:405`). Application debrief form holds local state without a key/reset when the selected application changes (`:2030`, `:2064`), risking old notes/saved state being shown for a new application. Global Start is rendered even in Debrief Review, where its handler only sets the phase already displayed (`:767`, `:819`). Custom listbox lacks arrow/Escape/focus management (`:1199`).

**Upgrade / acceptance:** Clearing context explicitly clears its ID and has a documented preserve/reset policy for manual inputs. Debrief drafts keyed by owner+application; switching A→B cannot reuse A's saved state. No no-op start button in review. Use native select or tested accessible combobox behavior, with all configuration states announced.

### IL-11 — P1 — Real-interview reflection is automatically converted into “proof” without user review

**Source-confirmed.** API supplies question confidence from overall feeling ×20 when no per-question confidence is sent (`app/api/agent/debriefs/route.ts:117`). Any question with ≥60 then auto-creates a Story Bank entry whose situation is attending the interview, action is generic “strengths” or a placeholder, and result is self-assessed confidence (`:165`). The active form sends no actual answer transcript or confidence (`interview-sim/page.tsx:2092`). A user feeling average can therefore receive a proof story that describes interview performance rather than a real work achievement. The form says saved reflection improves practice, not that a factual story is automatically published to their bank. New story also omits the source application/debrief IDs (`debriefs/route.ts:170`).

**Upgrade / acceptance:** Keep reflection as reflection. Offer a separate “Turn an answer into a story” draft with original notes, source debrief ID, missing fields, and explicit user confirmation. Never treat confidence or feeling as outcome evidence. Coverage/reuse must exclude unconfirmed/placeholder drafts.

## Findings: Story Bank

### IL-12 — P1 — Three primary Story Bank AI actions have no route implementation

**Source-confirmed.** UI calls `/api/agent/stories/extract`, `/match`, and `/quality` (`app/suite/agent/stories/page.tsx:350`, `:383`, `:415`). Route inventory contains only `stories/route.ts` and `stories/coverage/route.ts`; `next.config.js` has no API rewrites and `proxy.ts:174` passes authenticated API requests onward. `lib/story-intelligence.ts:236`, `:300`, `:347` contains useful helpers, but those helpers are not the missing HTTP handlers. Matching has a separate assistant path through `lib/story-search.ts:178`; that does not make this page's button work.

**Upgrade / acceptance:** Either wire authenticated, bounded, entitlement-aware routes to the helpers or hide the actions until ready. Owner-check requested sources; validate generated draft/match/quality payloads. Route-to-action contract coverage must include every visible button and malformed/provider-unavailable responses. Test normal app routing, not only the isolated preview that blocks these calls with a generic 503 (`lib/workspace-preview-response.ts:43`).

### IL-13 — P1 — “Proof” and privacy badges are heuristics and can become stale after edits

**Source-confirmed.** A baseline 18 points plus text length, numbers, tags, and linked role produce `proofScore` (`lib/story-bank.ts:217`); privacy is keyword matching (`:208`). UI calls this “N/100 proof” and “low privacy risk” (`stories/page.tsx:762`, `:769`). These are completeness/hint measures, not verification or a privacy review. On edit, existing story including old `proofScore`/`privacyRisk`/`competencies` is spread before updates (`story-bank.ts:459`), and normalization retains existing numeric/enum values (`:267`), so modified content does not recompute the claimed metadata despite the PATCH comment promising it (`app/api/agent/stories/route.ts:93`). API spreads unvalidated body into story creation (`:72`); TypeScript omission types alone cannot prevent callers supplying derived metadata.

**Upgrade / acceptance:** Separate factual status (user-confirmed, source-linked, draft) from completeness and automated privacy hints. Recompute versioned derived metadata on edit; server-authoritative fields must ignore client overrides. Never equate a metric-shaped number with truthful achievement. Test changing a strong story into incomplete/sensitive text and attempted client score injection. Label automated privacy checks as limited hints rather than a clearance.

### IL-14 — P2 — Handoffs do not carry the selected story, and source labels overpromise extraction

**Source-confirmed.** “Practice interview” / “Turn into resume proof” invoke `routeWithStory`, which only changes company/role/resume ID in ApplicationKitContext, then routes (`stories/page.tsx:431`, `:628`). It passes no story ID, selected answer, or factual content. Interview Studio does not consume that context hook. Extract choices “From resume/debrief/chat” only set `sourceType`; every choice still requires pasted text (`:341`, `:983`). Draft display would expose only title and action/situation before Save, not the whole generated STAR record (`:1013`). Composer exposes raw Application ID, Resume ID, Contact ID text fields (`:905`).

**Upgrade / acceptance:** Typed handoff contract with owner-checked story/source IDs, selected answer and target; destination visibly acknowledges the selected story. Use real item pickers for saved sources, with a distinct “paste” route. Review/edit every generated STAR field and supporting source before save. Replace raw IDs with named, searchable records. Existing destination flows must not silently overwrite confirmed source facts.

### IL-15 — P2 — Library state, deletion, and long-list access need recovery work

**Source-confirmed / source risk.** Story list requests 120 and ignores returned `hasMore` (`stories/page.tsx:255`, `:264`, `:601`; `lib/story-bank.ts:423`), hiding older records. Selection is a dependency of `loadStories`, so selecting triggers unnecessary reload (`stories/page.tsx:274`). No request sequence/abort guard prevents slower search/quality results replacing a newer selection (`:243`, `:411`); logging out simply returns without clearing existing stories (`:244`). Delete directly executes with no undo (`:322`, `:823`), and unsaved edits are discarded on selecting another card (`:607`). Impact of auth transitions depends on whether the shared shell remounts the page; no runtime claim is made.

**Upgrade / acceptance:** Cursor pagination/search with stable selection, owner-bound request cancellation, visible retry, reversible deletion, and unsaved-change handling. Test 121+ records, slow-old/fast-new requests, selection during quality review, and account switch while a request is pending.

## Findings: Skill Bridge and Memory

### IL-16 — P1 — Skill verification's business rule is not enforced server-side

**Source-confirmed.** Settings says applied challenges need 80+ (`skill-bridge/page.tsx:1531`), and a `verdictFor` helper encodes that (`app/api/skill-bridge/verify/route.ts:33`). However any enum-valid model verdict is accepted directly, only falling back to the rule for an invalid string (`:206`). Thus `quick_check + 60 + verified` is accepted if the model emits it. Client can edit prompt and switch challenge type without clearing/reissuing the prompt (`skill-bridge/page.tsx:1758`, `:1772`). There is no server-owned challenge ID binding difficulty, rubric, answer, and evaluation. Firestore rules also allow owner writes to entire `skill_verifications` and `study_progress` collections (`firestore.rules:27`, `:243`), including derived verification claims; this is integrity of the owner's evidence, not a cross-user data exposure finding.

**Upgrade / acceptance:** Server derives verdict from validated score/type, bound to a persisted challenge/rubric version. Distinguish custom practice prompts from assessed challenges. Separate user progress fields from server-written assessments in rules. Test inconsistent provider verdicts, quick→applied switching, old prompt reuse, client-forged scores, repeated attempt IDs, and cross-owner challenge IDs.

### IL-17 — P2 — Readiness is all-time best, and old heuristic records have no provenance migration

**Source-confirmed.** Readiness uses maximum historical proof/progress score (`skill-bridge/page.tsx:424`, `:453`); API preserves verified status forever, takes maximum score, and stamps `last_verified_at` even on unsuccessful attempts (`verify/route.ts:252`, `:268`). Source comments acknowledge previously fabricated grades may persist (`skill-bridge/page.tsx:440`), but comments are not migration evidence. Review-due is computed separately while “Maintain proof” wins over “Review due” in the next-action branch (`:457`). Users can read old best performance as current validated readiness.

**Upgrade / acceptance:** Display “best practice result” and latest result/date separately; freshness/review status must remain visible. Version assessment provenance and quarantine/relabel legacy heuristic records until audited. Preserve historical attempts but do not silently confer ongoing verification. Fixture coverage includes old no-provenance records, a later weaker attempt, overdue review, and genuine 0 scores.

### IL-18 — P1 — Plans are generated but the primary learning view hides the learning material

**Source-confirmed.** Plan generation creates daily tasks/resources/search suggestions/time estimates (`app/api/resume/study-plan/route.ts:103`). Drawer renders only the first two tasks as truncated text and no resources/time estimate (`skill-bridge/page.tsx:1719`). The only route to full plan is exporting to Memory, whose detail route is missing (IL-21). On export, an omitted URL becomes Markdown `(undefined)` and `searchFor` is ignored (`app/api/vault/export-plan/route.ts:39`), despite the generator explicitly allowing absent URLs (`study-plan/route.ts:92`). Memory's ad hoc Markdown parser does not convert Markdown links (`MemoryPanel.tsx:53`).

**Upgrade / acceptance:** Expandable day view with every task, safe real link or explicit search phrase, effort estimate, and exercise output; accessible link rendering and no `undefined` URLs. Save exact structured curriculum and render from it without a second generation. Test a day with 3+ tasks, long text, resource without URL, unsupported scheme, and empty/malformed schedule.

### IL-19 — P1 — Skill context is browser-global, and its interview handoff loses the target

**Source-confirmed; account contamination is a source risk needing runtime reproduction.** Skill gaps/JD/company come from the unscoped `tc_skill_gaps` localStorage key on mount (`skill-bridge/page.tsx:311`).
